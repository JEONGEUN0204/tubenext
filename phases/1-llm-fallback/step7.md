# Step 7: empty-state-copy

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `CLAUDE.md`
- `docs/UI_GUIDE.md` (**전부 읽어라.** 특히 "AI 슬롭 안티패턴" 표와 색상 표)
- `docs/PRD.md` (디자인 원칙)
- `src/app/page.tsx` (**이 step에서 수정할 유일한 파일**)
- `src/lib/viral.ts` (`rankViral`이 어떤 영상을 걸러내는지 — 최소 조회수 1만, 최소 구독자 100, 내 채널 영상 제외)
- `src/app/api/analyze/route.ts` (`viral`이 비면 기획안 생성을 건너뛰고 빈 배열을 돌려준다는 사실을 확인하라)

이전 step에서 만들어진 코드를 꼼꼼히 읽고, 설계 의도를 이해한 뒤 작업하라.

## 배경 — 실제로 관찰된 문제

실제 채널로 돌려보니 바이럴 영상이 0개가 나왔고, 그러자 화면에 이 문구가 떴다:

```
기획안 생성에 실패했습니다. 다시 시도해주세요.
```

**실패한 게 아니다.** 라우트는 `viral`이 비면 근거가 없으므로 기획안 생성을 **의도적으로 건너뛴다.**
지금 문구는 사용자에게 버그라고 알리고, 다시 시도하면 고쳐질 것처럼 말한다. 둘 다 사실이 아니다.
같은 결과가 또 나오고, 사용자는 YouTube 할당량만 300 units 더 쓴다.

이 step은 **빈 상태 문구를 실제 원인에 맞게** 고친다.

## 작업

`src/app/page.tsx`만 수정한다. 로직·상태·섹션 구조·컴포넌트는 건드리지 않는다. 문구와 조건 분기만 다룬다.

### 1. 기획안 섹션의 빈 상태 (현재 155행 근처)

지금은 `result.ideas.length === 0`이면 무조건 `기획안 생성에 실패했습니다. 다시 시도해주세요.`를 띄운다.
아래 두 경우로 나눠라.

**`result.viral.length === 0`일 때** — 근거가 없어서 안 만든 것이다:

```
참고할 바이럴 영상을 찾지 못해 기획안을 만들지 않았습니다. 이 채널의 검색 키워드로는 최근 30일 안에 조건을 넘는 영상이 없습니다.
```

**`result.viral.length > 0`인데 기획안이 0개일 때** — 이건 진짜 예외 상황이다. 기존 문구를 유지한다:

```
기획안 생성에 실패했습니다. 다시 시도해주세요.
```

### 2. 바이럴 섹션의 빈 상태 (현재 128~130행 근처)

지금은 `result.viral.length < MIN_VIRAL_SAMPLE`(3)이면 `이 주제는 최근 30일 표본이 적습니다.`를 띄운다.
0개와 1~2개는 사용자가 할 일이 다르다. 나눠라.

**0개일 때**:

```
최근 30일 안에 조회수 1만 이상인 관련 영상을 찾지 못했습니다. 검색 키워드: {키워드들}
```

`{키워드들}`은 `result.profile.searchKeywords`를 `, `로 이어 붙인 것이다. 키워드 배열이 비어 있으면 뒤의 `검색 키워드:` 부분을 통째로 빼라.
실제로 어떤 말로 검색했는지 보여주는 것이 요점이다. 키워드가 엉뚱하면 사용자가 바로 알아챌 수 있다.

**1~2개일 때**: 기존 문구 `이 주제는 최근 30일 표본이 적습니다.`를 유지한다.

### 스타일

- 두 문구 모두 기존 보조 문구와 같은 클래스를 쓴다: `mt-2 text-sm text-neutral-500`
- 색상·아이콘·이모지를 넣지 마라. 경고 배너로 만들지 마라.

## 검증 절차

1. 위 AC 커맨드를 순서대로 실행한다.
2. UI_GUIDE 체크리스트를 확인한다:
   - 이모지·아이콘·경고색·배너·모달을 추가하지 않았는가?
   - 새 애니메이션을 추가하지 않았는가?
   - 문구 스타일이 기존 보조 문구와 같은가?
3. 아키텍처 체크리스트를 확인한다:
   - `page.tsx`가 여전히 4가지 상태(`idle | loading | success | error`)만 `useState`로 관리하는가?
   - 섹션 순서와 컴포넌트 구조가 그대로인가?
4. 결과에 따라 `phases/1-llm-fallback/index.json`의 step 7을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- 결과가 비었을 때 자동으로 재요청하거나 재시도 버튼을 달지 마라. 이유: 무상태라 같은 입력이면 같은 결과가 나오고, 1회 분석마다 YouTube 할당량 약 304 units가 나간다(ADR-006, ARCHITECTURE.md의 할당량 예산).
- 빈 상태를 성공처럼 보이게 꾸미거나, 예시·더미 기획안을 채워 넣지 마라. 이유: 근거 영상이 없다는 사실 자체가 사용자가 알아야 할 정보다.
- `rankViral`의 임계값(최소 조회수·구독자 수)을 낮춰서 결과를 억지로 만들지 마라. 이유: ADR-005의 결정이고, 이 step의 범위도 아니다.
- `src/lib/`, `src/services/`, `src/app/api/`, `src/components/`, `src/types/`를 수정하지 마라. 이유: 이 step의 범위는 `src/app/page.tsx`의 문구와 조건 분기뿐이다.
- 기존 테스트를 깨뜨리지 마라.
